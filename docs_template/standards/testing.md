# 测试规范

## 最低要求

| 变更类型 | 测试要求 |
|----------|----------|
| 行为变化 | 至少补 1 个相关测试 |
| Bug 修复 | 优先补 regression test |
| Service 层逻辑修改 | 优先补单元测试 |
| Controller/API 改动 | 如适用，补集成测试 |
| 核心 SQL 改动 | 至少说明验证方法和边界数据 |

## 测试分层

```
┌─────────────────────────────────────┐
│         E2E / Integration           │  ← 接口级验证
├─────────────────────────────────────┤
│            Service                  │  ← 业务逻辑验证
├─────────────────────────────────────┤
│           Repository                │  ← 数据访问验证
└─────────────────────────────────────┘
```

## 评审要求

提交 review 时必须说明：

- 跑了哪些测试
- 哪些部分没有测
- 为什么跳过这些检查仍然可以接受

## 常用命令（根据项目类型调整）

| 项目类型 | 命令 |
|----------|------|
| Maven | `mvn test` |
| Gradle | `./gradlew test` |
| npm | `npm test` |

## 测试覆盖率

- 核心业务逻辑覆盖率应达到 **80%+**
- 新增代码必须附带测试
- 测试不完善的功能不允许发布
